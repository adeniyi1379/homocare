## Context
- User builds the Homecare Hospital Management System (Osogbo, Nigeria) as Next.js 16 (App Router, Vercel) + Supabase: patient intake/triage, nursing (vitals + administrations), pharmacy stock + dispensing, cashier billing with decoupled receipts, and an admin operations dashboard, with RBAC (receptionist/nurse/pharmacy/cashier/admin).
- The hospital is an EXISTING working clinic (Homocare Gracious Hospital, homocaregracioushospital.com). Patient IDs are entered MANUALLY by reception staff at registration — no auto-generated codes in the UI.
- Privacy constraints (hard requirement, enforced at DB + UI): drug names/quantities/internal costs NEVER appear on receipts or to the cashier; each dispense decrements stock automatically and flags low/out-of-stock at the reorder level.
- Brand (taken from the hospital's live site): primary deep navy `#13233B`, accent sky blue `#87CEEB`. Tailwind v4 brand tokens in globals.css, plus a modern clinical accent set `accent-500/600/700` (teal `#14b8a6/#0d9488/#0f766e`).

## Important Details
- Versions: next `16.3.5`, react `19.2.8`, `@supabase/ssr ^0.12.7`, tailwind `^4`, TS, Turbopack default. `.env.local` now exists (NEXT_PUBLIC_SUPABASE_URL + ANON_KEY) — build shows "Environments: .env.local".
- Next 16: session middleware is `src/proxy.ts`; `cookies()`, `params`, `searchParams` async.
- Server actions for `useActionState` MUST be `(prevState: ActionResult, formData: FormData) => Promise<ActionResult>`, `ActionResult = { error: string } | undefined`. Forms are client components in `src/app/*/forms.tsx` using useActionState + shared `src/components/form-ui.tsx` (FormError, SubmitButton w/ useFormStatus). Never bind a value-returning action to `<form action>` directly.
- Client components must NOT import `@/lib/auth` (server-only). Use `@/lib/roles` (Role, ROLES, ROLE_LABELS, homeForRole).
- Supabase untyped: normalize relation embeds with `oneOrNull(v)` (`src/lib/utils.ts`); cast RPC payloads via `as unknown as …[]`. RPC/param names must match schema (limit_count, user_id+new_role, item+delta).
- Brand tokens available as Tailwind utilities: `brand-50/100/200(…/#87CEEB)/300/400/500/600/700(#13233B)/800/900`. Typography: `Noto Sans` = `--font-sans` (body), `Figtree` = `font-display` (headings/wordmark/tiles) via next/font/google ("Medical Clean" pairing from the ui-ux-pro-max skill). Page bg `#f2f6fb` with fixed radial teal/blue glows on `body`. Buttons: shared CSS classes `.btn` + `.btn-primary`/`.btn-accent`/`.btn-ghost`/`.btn-danger`/`.btn-sm` (gradient navy primary, teal accent, soft shadows, 1px lift). Tables: add `.table-modern` to any `<table>` for a clinical look (slate-50 sticky-ready header, uniform cell padding, hover row, tfoot top rule). Patient codes rendered `text-brand-600` mono. - Receptionist page: "Quick Actions" buttons (Register Patient / Open Encounter) open modal pop-ups (`src/components/modal.tsx` — Escape/backdrop close, body scroll lock, fade+pop keyframes, reduced-motion off); the encounter form uses `PatientPicker` = TEXTBOX search across name/ID/phone with selectable results (NOT a dropdown); writes hidden `patient_id`. - Patient codes: fully MANUAL — the auto-gen trigger, `generate_patient_code()`, and `patient_code_counters` were REMOVED from `schema.sql`; `patient_code` is `text not null unique` (with a defensive `alter … set not null` for pre-existing installs). Reception renders a required "Patient ID / File number" input; duplicates rejected by the DB unique constraint.
- Admin control centre (tabs, /admin): Overview (KPIs, stock health, profitability, audit trail) + **Staff & Users** + **Intake Categories**. Staff tab: full user CRUD via security-definer RPCs — `admin_create_user(p_email,p_full_name,p_role,p_password)` (inserts into auth.users + auth.identities, profile auto-created by handle_new_user trigger, audit 'USER_CREATE'), `admin_update_user(p_user_id,p_full_name,p_role)` (name+role, updates profile AND raw_user_meta_data), `admin_reset_password(p_user_id,p_new_password)` (direct bcrypt set — staff can't reset on their own tab), `admin_set_user_active(p_user_id,p_active)` (banned_until lock, self-deactivate blocked), plus existing `set_user_role`; `get_users_admin` now returns `is_active`. Patterns: modal forms close on success via `submitted` ref + `useEffect(!state?.error)` (React 19 useActionState dispatch returns void — do NOT `await action(fd)`); modals are freshly mounted per open (state resets).
- Intake categories: new `treatment_categories(id,name unique,description,sort_order,active)` table, RLS select-all-authed + admin-write, seeded defaults (General Outpatient, Emergency, Antenatal, Immunization, Minor Surgery, Admission/Ward, Chronic Care). Reception Open Encounter **Category** is now a dropdown fed by active categories (was free-text). Admin categories tab: add/edit (name/description/order), Show/Hide toggle, Delete (confirm dialog; encounters keep the category label as text — no FK).

RLS additions in schema.sql (needs live re-run): `treatments_cancel_creator` redefined to also allow encounter_type change on own ACTIVE encounters, plus `treatments_update_encounter_receptionist_admin` (receptionist/admin, status='active' in WITH CHECK).
- Modal final sizing (both intake + encounter + pharmacy): `min-h-[70vh] max-h-[90vh] w-full max-w-3xl`, centered, header shrink-0, content `flex-1 overflow-y-auto`; Escape/backdrop/✕ close, body scroll lock, fade+pop (reduced-motion off).
- Shared modern UI (receptionist first, patterns reusable): `.reveal/.reveal-2/.reveal-3` staggered fade-up; page title gradient `bg-clip-text`; `Card` now overflow-hidden with 0.5px brand gradient top bar when titled; Quick Action tiles carry gradient bars + hover arrow; tables have hover rows + tinted header.
- Pharmacy dispense→administer hand-off (DIRECTED chain, matches "track the movement item→from whom→to whom→to which treatment"): `treatment_dispensations` gains `dispensed_to` (the nurse pharmacy hands it to) + `administered_by`/`administered_at` (nurse's confirm). Legacy `collected_*` leftovers are harmless. RPCs: `get_dispense_recipients()` (nurses list for the dispense picker, pharmacy/admin), `get_my_pending_dispensations(int)` (items handed to CURRENT nurse, not yet administered), `confirm_dispense_administration(p_dispense_id uuid)` (only the designated nurse or admin, once-only, sets administered_by/at), `get_my_dispense_history(int)` (nurse's own confirmed list). `get_pharmacy_log` + `get_item_usage` return the chain: `dispensed_by_name`, `dispensed_to_name`, `administered_by_name/at`. The pharmacy Dispense modal now REQUIRES "Hand off to (nurse)" via SearchPicker; nurse page shows "Items Dispensed to You · Pending Administration" (per-row "Item Administered" button → `confirmAdministration` in `nurse/actions.ts`, `router.refresh()`) + "My Pharmacy Administration History". Direct ward "Administer Dose" flow still coexists.
- Receipt: `REC-YYYYMMDD-XXXX`, balance = max(0, fee − paid), no drug line items, PrintButton + `.receipt` print CSS.
- `payment_enum` = ('cash','pos_terminal','bank_transfer'); cashier form options match (was fixed earlier — 'card'/'transfer'/'insurance' removed).
- RLS: drug costs hidden (treatment_dispensations no direct select; RPC-only). `get_dispensable_items` returns no cost to nurse. Vitals only nurse/admin.
